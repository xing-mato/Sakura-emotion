# 情绪池 · Sakura 插件

给角色一套**以「轮」为节拍**的情绪：她每回完一句话，由模型决定这一轮该往哪几根弦上加多少、
减多少。她从二十五种情绪里挑出「主·次·辅」三根表现出来，另外三根留作不表现的余韵，
用百分比显示在左侧栏的「情绪」页。时间不参与计算，只在"很久没说话"时作为一条事实递给模型。

    api: 4 · plugin id: sakuratools.emotion_pool · author: mato · 无第三方依赖

## 一、它解决什么

Sakura 原本的情绪是**每一轮临时推出来的**：模型读一遍人设和最近几轮对话，决定这句话用什么语气。
于是出现三种体感：

| 你看到的 | 实际发生的事 |
| --- | --- |
| 上一轮还在生气，下一轮发个表情包她就笑着接话 | 情绪**没有残留** |
| 一句话把她推到底，之后一直挂在那儿 | 情绪**没有回落** |
| 中间那层"有点闷、但还没生气"根本不存在 | 情绪**没有强度** |

这个插件补的就是那个"状态"：二十一根弦里此刻在場的主·次·辅、0~100 的百分比、只在判断时变。

---

## 二、怎么做到的（v2）

### 1. 以轮为单位，不是以秒

    她回复完成（sakura.host.chat.completed）
      → 读回这一轮：你说的原话、她的回复、距上一轮多久
      → 一次模型判断
      → 稀疏增减值落到池子里（"委屈 +24、失望 +10"，没提到的就是没变）
      → 下一轮注入的就是新值

没有半衰期、没有 ticker、没有"读一次掉一点"。**状态只在判断时变。**

为什么不做时间衰减：Sakura 不是人。她没有一个持续运行的时间感，两次对话之间她实际上是"不存在"的——
没有经历，就没有淡忘的理由。而衰减会把"上一轮刚受的委屈"稀释成"她好像没那么在意"，
这恰恰是"情感欠缺"的来源。

### 2. 时间只在缺席时有意义

判断的输入里有一行「上一轮至今：72 小时」。加多少生气、要不要委屈、还是只是淡淡一句"你终于来了"，
**由模型按她的人设决定**——"三天没来"和"三周没来"该有多生气，是性格问题，不该由插件常数决定。

### 3. 判断契约

    {
      "deltas": {"委屈": 24, "失望": 10}    ← 百分点，稀疏，单轮上下限 ±60
      "summary": "被放了鸽子，堵着"          ← ≤20 字，写进提示词
      "gist": "他说好陪她，又要走"           ← ≤24 字，进涟漪表
    }

判断失败（没配模型、请求失败、JSON 坏了）就**这一轮不动**——绝不退回关键词猜一个数顶上。

### 4. 涟漪

一次增减 ≥20 个百分点就留一条记录：什么时候、因为哪句话、哪根弦、动了多少。
最近两条会写进提示词，剩下的在设置页的「情绪涟漪」表里。

## 三、她看到的是什么

标准档（约 90 字）：

    【情绪】主·委屈 46%，次·无奈 22%，心境：等了一小时，心里发凉却还撑着。
    （这是你此刻的底色，不是台词：主决定这一轮的语气和取舍，次只影响措辞，辅几乎不表现；
    别把它念出来，让它从语气里透出来。强度低的时候宁可不表现，也别为了演而演。）

**为什么只有三个位置**：人在某一刻通常是一根主、最多再有一根次、偶尔一点辅。三根以上同时在场，
不是假的，就是自相矛盾的——那会让她既温柔又委屈又傲娇，除了「难以言喻」没有别的结果。
所以容量就是三个名额（state.MAX_MOOD）：名册外的情绪一律清零，谁进谁出由模型点名，
插件只负责「三」这个数，不替她判断该有谁。

平静时：

    【情绪】此刻没有哪根弦在被拨动，心境：平稳。
    （平静不等于冷淡，也不是没有脾气。）

详细档再加"最近的涟漪"与 Mem0 里的"相关往事"。

写这段文字只有一条硬规矩：**给行为，不给形容词**。"话变短、容易多想、等着被发现"会让她真的那样说话；
"你现在很委屈"只会被演成台词。三档措辞在 emotion_pool/taxonomy.py，可以直接改。

如果她的角色配置里允许语气标签（比如 中性/不满/害羞/请求/惊讶），
详细档会提醒模型让分段的 tone 跟着情绪走——TTS 和立绘会跟着变。

## 四、设置

设置 → 插件 → 情绪池。**没有任何一个输入框能改她的情绪值。**

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| 让她有自己的情绪 | 开 | 总开关；关掉后不再注入也不再判断，状态原样保留 |
| 写进提示词的详细程度 | 标准 | 极简 / 标准 / 细致，只影响长度 |
| 和 Mem0 长期记忆联动 | 关 | 不联动 / 只读 / 只写 / 读写 |
| 保留多少条情绪涟漪 | 16 | 记录表与"最近的涟漪" |

按钮只剩三个：

设置页只留一个无害的按钮：**测试长期记忆桥**。

「清零」和「导出运行日志」搬到了左侧栏那个「情绪」页的底部（仪表盘右下角），
因为**那里是我们自己的 UI，能弹真正的对话框**；设置页的按钮只能回一行字，
看不见就会被当成坏了、再点一次——两次点击等于没拦。

在仪表盘里点「清零」会弹：

    ┌ 清空当前情绪？ ─────────────────┐
    │ 不推荐这么做，但这由你。清零会把 │
    │ 此刻的情绪值全部归零；涟漪记录和 │
    │ 聊天记录都还在。                │
    │              [取消]  [确认清零] │
    └─────────────────────────────────┘

「导出日志」同理，对话框里先说明会包含聊天记录、可能含隐私。
- **测试长期记忆桥** —— 检查能不能通过工具目录找到 Mem0。

「看一眼她现在的内心 / 打开完整预览 / 打开状态文件」三个按钮已经删掉：
它们在设置页里解决的是一个已经有别处解决的需求（面板 + 状态文件本身就能看）。

v1 里那四个数字（反应强度、消退速度、最短保持、切换门槛）全部删了——它们是把工程参数甩给用户，
而且互相耦合，没人调得动；情绪怎么变本来就该是模型的判断。

## 五、仪表盘

装好启用后，**Sakura 设置页的左侧栏「行为」组里会多出一个「情绪」入口**（插件自己注册的一页）：

    主  委屈   ███████████─────────────────   46%
    次  无奈   █████────────────────────────   22%
    辅  —      ────────────────────────────     —
    ▸ 其余 19 种
    ──────────────────────────────────────────────
    上一次判断：2 分钟前 · 委屈 +8                 [刷新]

点开那行「其余 19 种」：

    主  委屈   ███████████─────────────────   46%
    次  无奈   █████────────────────────────   22%
    辅  —      ────────────────────────────     —
    ▾ 其余 19 种
       喜悦  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄   0%
       爱慕  ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄   0%
       ……（其余同理）
    ──────────────────────────────────────────────

- **在场的那三根摆在上面**，只有名字、条、百分比。「主」那行加粗——它决定这一轮的语气。
- **当前没有的情绪收进抽屉**：默认不占地方，点箭头才展开。展开后是二十一种的目录，
  它们此刻都是 0%——不是为了看数字，是为了知道池子里有哪些词。
- 平静时三个位置都是 **—**，抽屉里是全部二十一种。
- 真正的圆角胶囊条：8px 高、两端全圆、渐变填充。颜色跟情绪的分组走：
  暖（喜悦/爱慕/温柔/好奇/自信/害羞）、钝（无奈/无语/疑惑/尴尬/惊讶）、
  冷（委屈/失望/悲伤/生气/害怕/厌恶/担忧/孤独）、混（吃醋/傲娇）；抽屉里的条是虚线空槽。
- 只读，**不可拖动**。随手拨她的情绪这件事不该存在。
- 「刷新」= **请模型按最近 16 轮对话重新判断一次**（最多改三根），按钮会变成「想一想…」，等它回来。

### 它怎么接进来的

宿主对插件页面只开放 form / module / record-table / connection-status 四种画法，没有图表组件。
所以仪表盘走 **module**：

    presentation = {"component": "module", "source": "<整段 JS 源码>"}

宿主把它当 ES module 导入，调用 mount(context)，返回值要有 element 与 dispose()。
数据走一个只读的 data 字段 payload，模块用 read("payload") 取；刷新按钮调用插件的 refresh 动作。

两个踩过的坑：**页面 CSP 是 style-src 'self'，没有 unsafe-inline**——往 DOM 里塞
`<style>` 会被静默拦掉（页面就变成一串裸文字），必须用构造式样式表
（new CSSStyleSheet + document.adoptedStyleSheets）；而 CSSOM（element.style.width）不受这条限制。

## 六、和 Mem0 长期记忆

**结论**：能借它的工具，借不到它的接口。

- Mem0 的 manifest 里 provides 是空的，没有对外 service key；读它的数据目录越界。
- 它公开的只有 sakura.host.tools 里的 memory_search / memory_remember 等工具，
  而 tools 的 catalog + execute 是宿主 SDK 的公开面。

所以用 catalog() 发现、execute() 调用：

| 方向 | 调用 | 什么时候 | 闸门 |
| --- | --- | --- | --- |
| 读 | memory_search(query) | 每轮判断后找相关往事，**下一轮**接在情绪后面 | 文本 ≥6 字；480 秒过期；timeout 8 秒 |
| 写 | memory_remember(content, layer=episodic) | 一次增减 ≥40 个点的情绪事件 | 距上次 ≥5 分钟且 ≥3 轮，一次一条 |

**默认关着**：读要打一次向量检索，写会把情绪事件永久塞进记忆库。建议先开「只写」用几天再决定。

限制：这是在工具目录上搭的桥，Mem0 改工具名就会静默失效（日志里有"找不到可用的记忆工具"）；
读回来的往事下一轮才用得上（慢路径跑在回复之后）。

## 九、排错

| 现象 | 先看这里 |
| --- | --- |
| 情绪一直不动 | 有没有配聊天模型？没模型时一律不判断（面板「上一次判断」会一直是"还没有"） |
| 面板一直是 0% | 同上；或这一轮模型判断回了空 deltas（日常寒暄本来就该是 0） |
| 「刷新」没反应 | 看面板底部那行字：点下去会先显示"正在请她重新想一想…"，回来后显示模型给的结论（"她重新想了想：失望 +32"）或失败原因（"没有可用的聊天模型…"）。如果连这行都没变，说明前端模块没挂上，看日志里的仪表盘登记错误 |
| 「刷新」提示没有模型 | 设置 → 模型服务里选一个聊天模型 |
| 刷新后没变化 | 模型认为不用改；涟漪表的"变化"列会显示它给了多少 |
| 日志里「情绪判断失败」 | 看 reason_code；常见是没选模型或额度用尽 |
| 面板数字和聊天对不上 | 两种可能：① 池子只进不出——旧版判定只在加水，2.2.2 起提示词要求它主动给已无证据的高值写负数；② 刷新重画过——2.2.2 起刷新最多改三根，且单根不许虚高。想立刻清干净：设置页点一次「把她归零」 |
| 日志里 deltas 一直是 {} | 2.2.2 之前的老毛病：宿主的日志净化器只接受 ASCII 键名，中文字典会被整条丢掉。现在改打成文本（委屈=+24,失望=-10） |

日志关键字：情绪池已就绪、情绪判断失败、刷新时的情绪判断失败、情绪判断的回复不是 JSON、
长期记忆检索失败、情绪记忆写入失败。

## 十、设计取舍

- **为什么不让模型直接"设置情绪"？** 情绪应该在她说话之前就已经在影响她，而不是中途改一个变量。
- **为什么判断在回复之后？** 放在之前就得阻塞这一轮；放在之后完全离线，还能读到"她实际怎么回的"。
  代价是这一轮用的仍是上一轮结束时的状态——她当下的反应由模型在台词里完成，池子只负责连续。
- **为什么删掉关键词快评？** v1 的快评是手搓的分贝表，中文里"讨厌""算了"高度依赖语境，
  误判会直接表现成"莫名其妙就委屈了"。交给模型判断，本地只做夹紧和去重。
- **为什么是这二十一种、不用 PAD？** 最初十种来自情绪种类清单，它们覆盖了"有对象感"的中文情绪
  （委屈、失望在 PAD 里反而糊成一团）。但十种不够：她天天在演"无奈"（角色卡里
  `reply.tones` 就写着 中性/无奈/坚定），而十种里没有这个桶，模型只能把它塞进失望（太冷）
  或委屈（太软）。2.1 补的六根都来自同一条线索——**分类要覆盖她真能表现出来的那些**：
  无奈、无语是她的默认反应，自信是导航员的本分，温柔是对着你的时候，疑惑是听不懂的时候，
  吃醋是"在意"长出来的（所以单独配色，不算敌意）。
  2.2 又补了五根，都是"她本来就有、旧分类里没桶"的：担忧（替对方悬着，不是害怕）、
  尴尬（想翻篇，不是害羞）、孤独（没有人在，不是悲伤）、惊讶（短情绪）、
  傲娇（表面否认、内里靠近，所以和吃醋一起放在"混"）。
- **惊讶为什么单独提一句？** 它是短情绪：上一轮有值、这一轮没有新的意外，模型自然会把它降下去。
  插件只提醒它「别因为没人管就一直挂着」，**降多少由模型判断**——写死一个 -15，就成了插件在替她衰减，
  那正是 v1 的做法。
- **池子会满吗？** 会。所以 v2.2.2 起判定提示词里写了两条出水口：某根已 50% 以上而这一轮拿不出
  任何支持它的证据，就得写负数把它降下来；同时在场（≥10%）的弦一般不超过 3~4 根。
  没有这两条，「每轮 +15、几乎不写负数」会让二十一根弦一起涨到高位——她看起来会既温柔又委屈又傲娇，
  除了「难以言喻」没有别的结果。
- **刷新会重画她吗？** 不会。刷新最多改三根，且绝对值必须落在和每轮同一个刻度上（最高参考档 40~60）：
  被哄好了是 30~50 的温柔，不是 87。
- **为什么只留三个位置？** 人同时只有一根主情绪，最多再有一根次、一点辅。旧版让她同时挂着
  十根弦（温柔 87、喜悦 50、傲娇 37……），除了「难以言喻」没有别的结果——那不是复杂，是假。
  所以容量写进数据结构：名册外一律清零，谁进谁出由模型点名。插件不判断该有谁，只判断「三」。
- **加不加、加多少，谁说了算？** 只有模型。插件不预设任何一根弦会自动涨落，也不按时间衰减：
  每一轮的值都是它重新判断出来的。这也是傲娇不设「克制角色最多 20」这种上限的原因——
  池子就是池子，往里倒水的只有她。
- **为什么注入只带四根？** 二十一根全写进去就没人在看重点了。前四根给数字，第五到第七根只报名字，
  第八根起不提。真正在场上的一般不超过四五根。

已知限制：

1. 每个回合一次模型调用（很小的 JSON），没配模型时插件不产生任何情绪。
2. 情绪按角色存，不按会话存：同一角色多个会话共享情绪。
3. 只影响文本语气与允许范围内的 tone 标签，不直接驱动立绘/表情。
4. 刷新是"补"不是"重算"：它会补你没判断过的部分，不会推翻已经沉淀的情绪。
